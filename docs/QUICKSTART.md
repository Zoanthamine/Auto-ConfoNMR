# ConfoNMR 快速使用

**自动化构象加权核磁计算与候选结构评估**。本说明面向已经完成集群配置的用户；首次安装先读 [迁移配置](MIGRATION.md)。命令中的 `/path/to` 和项目名称均需替换为自己的实际路径。使用 Linux Bash，保存文件为 UTF-8、脚本为 LF 换行。

## 1. 准备候选结构

每个候选一个完整的三维 `.pdb`，包含氢原子、元素列和正确的键连 `CONECT`。检查电荷、质子化状态、立体构型，不要把多个分子模型放在同一个 PDB。文件名使用英文、数字、下划线，例如 `candidate_A.pdb`、`candidate_B.pdb`。把本次全部候选放进一个单独的输入文件夹，避免混入其他 PDB。

上传到集群后，运行模板中的唯一建项目入口：

```bash
cd /path/to/ConfoNMR
bash 00_new_project.sh
```

依次输入：

|提示|填写或选择|说明|
|---|---|---|
|新项目英文名称|例如 `NMR_demo_20261012`|只含英文、数字、下划线、短横线；项目不能已经存在|
|PDB 所在目录|例如 `/home/user/inputs/demo`|填写集群路径，不是 Windows 路径|
|确认全部候选|核对列出的文件后输入 `yes`|每个文件成为一个候选|
|总电荷|中性填 `0`|不是局部原子电荷|
|自旋多重度|闭壳层通常填 `1`|其他体系需自行确认|
|DFT 最多构象数|默认 `6`；`0` 表示全部|这是成本预算，不保证收敛覆盖全部构象空间|
|聚类档位|`1` 粗分类；`2` 细分类|默认 1，沿用旧主流程；不是 STS 碳分类|
|NMR 方案|`1` PCM/G09兼容；`2` PCM/G16；`3` SMD/G16|日常沿用已核对旧方案选 1；2、3 用于单独对照项目|

创建成功只会准备项目，**尚未提交计算**。终端会显示实际项目位置。

## 2. 检查配置，再提交

进入刚才显示的项目目录，用文件编辑器打开 `project.ini`。中文注释说明每个选项；通常只核对电荷、多重度、构象预算、核数、内存和输出路径。核数与内存必须符合本集群节点限制。

|需要查看的文件|核对内容|
|---|---|
|`inputs/`|候选是否齐全，结构是否正确|
|`project.ini`|本次科学选项和计算资源|
|`计算方案.md`|实际方法、聚类阈值、校准差异|
|`参数预览/`|三种 NMR 的实际关键词；坐标占位符用于预览，不是生产输入|

```bash
cd /path/to/projects/NMR_demo_20261012
bash 01_submit.sh
```

看到 `Submitted 作业号` 和 `提交记录.json` 才表示已提交。它先检查输入、软件和活动作业；失败先读 `运行日志/submit_*.log`，不要连续重复提交。

## 3. 查看进度和过程文件

```bash
bash 02_status.sh
```

查看 `计算总览.html`、`运行日志/run_*.log` 和 `过程文件/`。这里直接保存 Gaussian、ORCA、采样、Shermo、构型及布居的实际文件。02 刷新状态和索引，不提交计算、不复制整批文件。总日志保留进度与搜索/聚类输出，量化详情请打开独立软件日志。

## 4. 准备实验数据和显式归属

实验表可以在计算期间准备；**比较必须等所有候选计算完成并验收后**进行。

|文件|准备方法|
|---|---|
|`experiment.csv`|复制 `experiment.template.csv`，填 `signal,nucleus,ppm`；每个实验信号一行|
|`assignments.csv`|复制 `assignments.template.csv`；为每个候选、每个信号填写原子号和分类|
|`experiment_upper.csv`、`experiment_lower.csv`|两个实验样品分别填写这两个文件；此时不要再留同一数据的 `experiment.csv`，否则也会单独比较|

`atoms` 使用计算原子号，从 `过程文件` 中的 `atom_map.json` 核对到原 PDB 序号；等价甲基的三个氢写为 `4;5;6`，**在同一单元格**。不要按位移大小排序配对。甲基的实验信号填一行，不能复制成三条独立证据。

完整 CSV 示例、DP4+ 的 sp2/sp3 判断及 STS 十类碳名称见 [详细使用说明](USER_GUIDE.md)。上下样品归属不同，可在 `project.ini` 中分别填写 `upper_assignments` 和 `lower_assignments` 文件名。

## 5. 验收后比较，再集中保存

核对所有候选 complete、PBS 退出码为 0、Gaussian/ORCA 正常结束、无虚频、布居和为 1、无未解释的采样/结构异常。具体清单见详细说明。

```bash
bash 03_compare.sh
bash 04_collect.sh
```

03 使用现有屏蔽数据，不重新计算量化；每个实验点输出独立的 `results/点名_时间戳/`。01、02 为 DP4+，03 为仅 13C 的 STS。`最终结果/最新_*_结果位置.txt` 指向各点最新结果。工作簿需用 Excel 打开并重算公式；JSON 中的概率由脚本直接计算。

04 更新构型、权重、索引及结果汇总；过程文件已经是实际文件，包含大轨迹和检查点。备份整个项目目录；不要只备份结果表。历史旧项目仍需同时备份旧 scratch。

遇到失败：保留原项目、输入、输出和提交记录，先诊断日志；活动作业不能再次提交。已有计算后修改科学条件应新建项目。仅更换实验表/归属可以重新运行 03。
