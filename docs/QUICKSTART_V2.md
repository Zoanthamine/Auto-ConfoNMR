# Auto ConfoNMR V2.1 简明操作 SOP

## 第一次配置（一次）

复制`config/cluster.example.json`为`config/cluster.json`，填写本人软件、Python、项目与scratch路径、module、Gaussian环境脚本、PBS队列及节点资源，详见[MIGRATION.md](MIGRATION.md)。准备已合法安装的软件和辅助资源。Python安装`requirements.txt`；ECD还需要`requirements-ecd.txt`。本版提供PBS提交器。

## 1. 准备结构

每候选一个PDB，检查氢、坐标、编号、电荷及多重度，上传到同一个独立输入文件夹；不要混入旧结构。没有实验数据也能先计算。

## 2. 建项与模块选择

在模板目录运行：

```bash
bash 00_new_project.sh
```

| 提示 | 要准备/输入什么 |
|---|---|
| 项目名称 | 独立英文名，例如Molecule_V2_20261013 |
| PDB目录 | 本次候选目录的完整集群路径 |
| 确认候选 | 核对结构后输入yes |
| 总电荷/多重度 | 按真实分子填写；中性闭壳层通常0/1 |
| 基础模块 | 0现有NMR（默认）；1单独构象 |
| 构象布居（基础1） | 1快速GFN2电子能；2精修自由能（默认） |
| DFT预算 | 默认6；0全部；快速档不使用 |
| 导出数量 | 默认前6个构象，可改正整数 |
| 增加J | 精修模式输入y启用，默认n |
| 增加ECD | 精修模式输入y启用，默认n |
| 聚类档位 | 1粗（默认）或2细；细分类不自动增加预算 |
| NMR方案 | 1旧PCM/G09兼容（默认）；2 PCM/G16；3 SMD/G16；只影响基础0 |

建项不提交计算。V2.1提交/正式比较先检查队列再同步配置；--check-only不写计算配置或预览。0/1二选一，J/ECD可同时附加到精修基础0或1；快速档不加J/ECD。

## 3. 核对配置

在新项目用MobaXterm编辑`project.ini`：`[计算]`含预算、温度、核数/内存；`[模块]`含开关和ECD方法/态数/溶剂；`[模块后处理]`含前N数量、J探索开关及ECD展宽/显示参数。后处理项可在计算结束后修改再导出；计算项开始运行后需新建项目。

打开`计算方案.md`、`模块选择.json`和`参数预览/`检查实际关键词。J独立计算气相B3LYP/6-31G(d,p)，ECD默认SMD甲醇，不继承NMR溶剂。

## 4. 提交一次

在新项目运行：

```bash
bash 01_submit.sh
```

保存作业号。预检/提交失败先读`运行日志/submit_*.log`，不要反复提交；已有活动作业会被拦截。

## 5. 查看

```bash
bash 02_status.sh
```

打开`计算总览.html`。总日志`运行日志/run_*.log`显示进度、搜索、聚类和错误位置；Gaussian/ORCA正文保存在`过程文件/`内的独立日志。全部候选结束后自动导出计算数据；没有实验表不产生实验比较。

## 6. 准备实验表与重新导出

| 目的 | 需要的正式文件 |
|---|---|
| DP4+/STS | experiment_样品名.csv，以及assignments_样品名.csv或共用assignments.csv |
| dJ-DP4 | [对比] experiment/assignments指定的一组C/H表（默认experiment.csv、assignments.csv），另加experiment_j.csv、assignments_j.csv；不自动选择某个多样品表 |
| ECD叠加 | experiment_ecd.csv：波长nm、Δε；可不提供 |
| 更多/更少构象坐标 | 只改top_n，不需要实验表 |

从`.template.csv`复制成同名正式CSV填写，列名、单位和示例见[MODULES.md](MODULES.md)。原子归属使用本次`sampling/atom_map.json`的`calculation_atom`。不要按位移排序配对。

J默认输出矩阵和输入表。审核DFT几何/Shermo布居与原文MMFF校准差异后，设`coupling_allow_exploratory=true`才会给探索概率；它与DP4+是不同分支。ECD默认缩放1.0/平移0，不裁剪实验；mdeg不能直接填入Δε列。

```bash
bash 03_compare.sh
```

只读取已完成日志，不重跑量化。所有基础模式都能在没有实验表时用此入口刷新前N坐标及原始计算导出；有正式实验表时会严格核对归属及内容。计算尚未全部结束时此入口会停止，应继续用02查看。

## 7. 保存与下载

```bash
bash 04_collect.sh
```

下载`最终结果/`、`results/`、布居CSV、文件索引及配置/哈希。模块目录：

- `最终结果/附加模块/conformers/`：XYZ、全集比例、子集混合与覆盖。
- `最终结果/附加模块/coupling/`：J矩阵、逐构象J、独立屏蔽、工作簿及探索概率/误差。
- `最终结果/附加模块/ecd/`：跃迁、曲线CSV、PNG/SVG和元数据。

新建项目的实际计算文件直接保存在本项目`过程文件/`，包括大轨迹、checkpoint、Gaussian/ORCA及Shermo文件；不依赖外部scratch链接。04另外提取易读XYZ、刷新结果快照和文件索引。长期保存应下载整个项目，或按索引选择完整复现所需文件。改变计算模块或科学参数时另建项目；不覆盖V1或活动任务。

## 遇到问题先看哪里

| 现象 | 操作 |
|---|---|
| 01预检失败、没有作业号 | 查看submit日志中的缺失软件/环境/资源；修正本人的配置，再预检提交 |
| 已有作业号、尚未结束 | 用02和队列确认状态；不要再次运行01或03 |
| 阶段失败 | 记录作业号和总日志末尾，打开其指向的独立软件日志；先确认作业已停止，保留整个失败阶段再诊断 |
| 03提示另有计算/后处理占用 | 不删除锁或receipt；确认队列和计算节点进程，等待占用方结束 |
| 崩溃后始终提示占用 | 请维护者检查过程文件/.workflow.guard/owner.json的主机、进程、作业号和时间，确认所有相关作业及后处理停止后，把残留guard移入项目历史目录，再重新运行入口 |
| 只有J矩阵，没有概率 | 先检查C/H/J实验表及显式原子归属；默认不开探索概率，不能用改开关代替数据审核 |
| ECD图没有实验线 | 未提供正式实验CSV仍会输出计算图；检查文件路径、列名和Δε单位 |

V2在共享文件系统上使用统一目录互斥；系统返回ENOLCK时仍保留该互斥，不再把锁服务不可用误报为另一个计算。它不会自动夺取崩溃后残留的锁。

## V1.2多样品接口

基础NMR可准备任意数量experiment_样品名.csv，配套assignments_样品名.csv或共用assignments.csv。先运行bash 03_compare.sh --check-only，计算完成后再03正式比较，04收集所有样品与历史。J/ECD使用各自指定表，不混入位移样品。详见[MULTISAMPLE.md](MULTISAMPLE.md)。02按真实阶段回执显示当前构象和软件日志。单独构象/无实验时不需要填写实验表。

J工作簿同时提供原始矩阵、仅用于³JHH的整页经验标度和Bally跨基组参考页；两页独立从原始值生成，不串联标度。实际普通基组未加+1s。详见[README](../README.md)。
